# AgentHub - 多 Agent 协作平台

## 课题概述

在大模型与 AI Agent 技术快速发展的背景下，多 Agent 协作已成为提升复杂任务执行效率的重要方向。

本课题聚焦 AI 驱动的开发与协作场景，要求学生基于统一适配器层与主流 Agent 平台（如 Claude Code、Codex），打造一个 IM 聊天式的多 Agent 协作平台 `AgentHub`。

`AgentHub` 需要提供类似飞书、微信的自然交互体验，支持单聊、多会话并行，以及通过 `@` 指令实现的群聊协作；同时集成 `Orchestrator` 协调器进行任务拆解，并提供代码 Diff、网页预览及一键部署等全流程能力。

课题不仅考察功能完整度与用户体验，也强调参赛者在 TRAE 协作、Prompt 工程及架构选型中的创新思考与实践。

## 课题背景

通过对话式交互创建网页、Workflow 等产物，正在成为 AI 产品的重要形态。本课题要求构建该业务场景的简化实战版，即一个面向开发与协作场景的多 Agent 平台。

平台采用 IM 聊天作为核心交互范式。用户像使用飞书、微信一样，通过新建对话、发送消息的方式与不同 AI Agent 交互。每个 Agent 都是一个独立的"聊天对象"，平台需要支持以下体验：

- 新建对话：创建新的聊天会话，并选择或指定要对话的 Agent，如 Claude Code、Codex、OpenCode 等。
- 多会话并行：同时开启多个对话窗口，分别与不同 Agent 处理不同任务。
- 群聊协作：在一个对话中 `@` 多个 Agent，由主 Agent（`Orchestrator`）自动协调分工，多个 Agent 依次回复各自产出。
- 上下文连续：每个对话保持完整聊天历史，Agent 能基于历史消息理解上下文，支持多轮迭代修改。
- 产物内联：Agent 回复不仅是文本，还可以内联展示代码 Diff、网页预览卡片、文件附件等富媒体产物，用户可直接在聊天流中预览和操作。

平台需要同时接入市面主流 Agent 平台（如 Claude Code、Codex、OpenCode 等），通过统一适配器层屏蔽 API 差异，并支持用户自建 Agent。所有 Agent 产出，如代码、网页、文档、PPT 等，都应支持实时预览、代码二次编辑和一键部署发布。

## 核心功能

### 1. IM 聊天式交互（核心体验）

| 功能 | 说明 |
| --- | --- |
| 对话列表 | 左侧会话列表，支持新建、置顶、归档、搜索，并按最近活跃时间排序 |
| 单聊模式 | `1v1` 与单个 Agent 对话，适合明确任务，如"用 Claude Code 写一个 React 组件" |
| 群聊模式 | 一个对话中包含多个 Agent，通过 `@` 指定或由 `Orchestrator` 自动分派，Agent 依次回复 |
| 消息类型 | 文本、代码块、图片、文件附件、网页预览卡片、Diff 视图卡片、部署状态卡片（可选） |
| 消息操作 | 回复、引用、重新生成、复制代码、一键应用 Diff、展开预览 |
| 上下文管理 | 聊天历史自动作为上下文传递给 Agent，支持手动 pin 关键消息作为长期上下文 |

### 2. 主 Agent 协调器（Orchestrator）

- 在群聊模式下，自动理解用户意图，将复杂任务拆解并分派给合适的子 Agent。
- 子 Agent 完成后，由 `Orchestrator` 聚合产出并在聊天流中汇报结果。
- 支持并行调度、失败降级、代码冲突处理。

### 3. 多 Agent 接入

- 提供统一适配器层，至少接入 2 个主流 Agent 平台，如 `Claude Code + Codex` 或 `Claude Code + OpenCode`。
- 支持用户自建 Agent，可通过对话式方式设定 `System Prompt` 与工具集。
- 每个 Agent 在聊天列表中显示为独立的"联系人"，具备头像、名称与能力标签。

### 4. 产物预览与编辑

- Agent 回复中支持内联产物预览卡片，如网页 `iframe`、文档渲染、PPT 浏览（P2）。
- 支持点击卡片展开全屏预览或进入代码编辑器。
- 支持 Diff 视图、版本历史、对话式局部修改（P2），例如选中代码后直接在聊天中描述修改需求。

### 5. 部署发布（P2）

- 在聊天中直接发送"部署"指令，Agent 返回部署状态卡片。
- 支持一键生成预览 URL、静态站点部署、容器化部署或源码打包下载。

### 6. 多端支持（P2）

| 平台 | 定位 |
| --- | --- |
| Web 端 | 主力端，提供完整 IM 体验、代码编辑与全功能能力 |
| 桌面端 | 支持本地文件访问、系统通知、Agent 进程管理 |
| 移动端 | 提供轻量 IM 体验，支持查看对话、审批确认与产物预览 |

## 考察要点

| 维度 | 权重 | 评判要点 |
| --- | --- | --- |
| AI 协作能力 | 30% | 是否沉淀出与 AI 协作的 Spec、Skill、Rules 等协作规范 |
| 功能完整度 | 25% | IM 核心体验是否流畅，多 Agent 调度是否跑通 |
| 生成效果质量 | 20% | 聊天 UI 体验与产物预览效果是否优秀 |
| 代码理解度 | 15% | 答辩时能否清晰解释架构选型与核心逻辑 |
| 创新与产品感 | 10% | 是否具备超预期功能点、体验优化或详细的产品设计方案 |
