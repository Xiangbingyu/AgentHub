# 提示词注入架构

## 一、目标

这份文档只解决一个问题：

- 如何在 AgentHub 的运行时，把 `Agent`、`Plan`、`InputEvent`、`tool` 以及运行环境信息，稳定地组装成一份动态提示词上下文。

这里的目标不是设计完整的模型调度系统，而是先定义一套清晰的 prompt 注入分层，能够支撑：

- `orchestrator` 的需求澄清、计划生成与任务分发
- `worker` 的编码执行、直接对话和任务回传
- `Plan` 直接进入动态上下文
- `worker loop` 注入局部计划视图
- `tool` 的使用规则被显式注入给模型

## 二、总原则

- `prompt` 负责约束模型“怎么做”
- `loop` 负责决定系统“下一步怎么走”
- `tool` 负责执行具体动作，不负责全局控制流
- `Plan` 是运行时上下文的一部分，不是像 skill 一样每轮动态读取的外部资源
- `worker loop` 只拿局部计划视图，不需要完整展开全局 plan
- `continue / wait / stop` 永远由 runtime 计算，不由模型直接输出

## 三、注入分层

建议把提示词注入拆成六层：

```text
provider prompt
+ environment prompt
+ instruction prompt
+ skills prompt
+ mode prompt
+ context prompt
+ tool prompt
= final prompt
```

### 1. Provider Prompt

作用：

- 贴合模型或框架的基础行为规范
- 作为最底层的 provider 差异化 prompt

第一期可以先只保留一层基础 prompt，后续再按 provider 细分。

### 2. Environment Prompt

作用：

- 注入运行环境事实

建议包含：

- `run_id`
- `agent_id`
- `agent_kind`
- `workspace_id`
- 当前工作目录
- 当前平台
- 当前时间

### 3. Instruction Prompt

作用：

- 注入 AgentHub 的系统级业务规则

建议包含：

- `run_input` 是统一入口
- `orchestrator` 负责规划和发配
- `worker` 负责执行和写代码
- `worker` 不能发配子任务
- `plan_tool` 负责全量覆盖计划
- `loop` 只负责控制流

### 4. Skills Prompt

作用：

- 注入当前 Agent 的能力说明

例如：

- `orchestrator`
  - requirement analysis
  - task breakdown
  - plan maintenance
- `worker`
  - code editing
  - testing
  - implementation

### 5. Mode Prompt

作用：

- 注入当前运行模式约束

建议最少区分：

- `orchestrator mode`
- `worker mode`

#### orchestrator mode

约束：

- 负责澄清需求
- 负责生成和更新计划
- 可以调用 `plan_tool / question_tool / delegate_tool`
- 不直接承担业务实现

#### worker mode

约束：

- 可以直接和用户对话
- 可以写代码、改文件、跑测试
- 不能调用 `delegate_tool`
- 不维护全局 Plan

### 6. Context Prompt

作用：

- 注入当前运行所需的实时上下文

#### 6.1 Plan Context

`Plan` 应直接进入 agent 的动态提示词上下文。

建议注入内容：

- 当前 `title`
- 当前 `goal`
- 当前 `summary`
- 当前 `steps`
- 当前 `status`
- 当前 `workspace_id`
- 当前 `run_id`

#### 6.2 Worker Local Plan

`worker loop` 不需要完整展开全局 plan，而应注入当前任务相关的局部计划视图。

建议包含：

- 当前子任务标题
- 当前子任务目标
- 与当前子任务直接相关的步骤
- 当前允许的工具边界

#### 6.3 Input Event Context

把当前输入事件转换成模型可消费的上下文片段。

建议支持：

- `user_input`
- `worker_callback`

### 7. Tool Prompt

作用：

- 告诉模型每个 tool 怎么用
- 告诉模型什么时候该用哪个 tool

建议至少包含：

- `plan_tool` 的结构化快照规则
- `question_tool` 的提问边界
- `delegate_tool` 的发配边界
- `code_tool` 的执行边界

## 四、Prompt 组装器

建议新增一个统一的 `PromptAssembler`：

```text
app/runtime/prompt_assembler.py
```

### 职责

- 按顺序拼接各层 prompt
- 将 `Plan` 直接注入 dynamic context
- 将 `worker` 的局部计划视图注入到 worker prompt
- 将 `InputEvent` 转成上下文片段
- 将工具说明拼入最终 prompt

### 建议方法

```text
assemble(runtime_bundle, input_event, plan=None, subtask=None) -> str
```

### 推荐拼装顺序

```text
provider prompt
-> environment prompt
-> instruction prompt
-> skills prompt
-> mode prompt
-> context prompt
-> tool prompt
-> final prompt
```

## 五、与 loop 的边界

- prompt 决定模型“怎么做”
- loop 决定系统“下一步怎么走”
- tool 决定具体动作如何执行

因此：

- `question_tool` / `delegate_tool` 通常会让 loop 返回 `wait`
- 最终回复且无待处理 tool call 返回 `stop`
- 其余需要继续内部推进的情况返回 `continue`

## 六、文件级建议

```text
app/
├─ prompts/
│  ├─ provider/
│  ├─ environment/
│  ├─ instruction/
│  ├─ skills/
│  ├─ mode/
│  ├─ context/
│  └─ tools/
└─ runtime/
   └─ prompt_assembler.py
```

## 七、一句话总结

AgentHub 的提示词注入，不是把一大段固定 prompt 写死，而是在 runtime 里通过分层组装，把 `Provider / Environment / Instruction / Skills / Mode / Context / Tool` 拼成最终 prompt，其中 `Plan` 直接进入动态上下文，`worker` 额外拿局部计划视图，`loop` 只负责控制流判定。
