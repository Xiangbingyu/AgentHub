# 重构指南

## 原则

重构必须逐步进行，禁止一次性大规模修改代码。每次重构应该专注于一个目标，并确保每一步都能正常运行。

### 核心原则
1. **小步快跑** - 每次只修改一个文件或一个模块
2. **保持功能不变** - 重构不改变现有功能，只优化代码结构
3. **及时测试** - 每一步修改后都要验证功能正常
4. **提交记录** - 每次重构单独提交，便于回滚

## 重构步骤

```
1. 识别目标    → 确定要重构的代码和原因
2. 制定计划    → 拆分为多个小步骤
3. 逐步实施    → 每次只改一处
4. 验证功能    → 确保功能正常
5. 提交代码    → 记录重构过程
```

## 禁止的重构方式

```bash
# 错误示例：一次性修改多个文件
- 批量重命名多个文件
- 一次性迁移整个模块
- 同时修改多个不相关的组件

# 正确示例：分步骤进行
- 第一步：只修改组件A的命名
- 第二步：只修改组件A的引用
- 第三步：验证组件A功能正常
- 第四步：提交代码
```

## 常见重构场景

| 场景 | 重构方式 |
|------|----------|
| 组件拆分 | 先导出新组件，原组件引用新组件，逐步迁移 |
| Hooks抽取 | 先在原组件内实现，逐步抽取到独立文件 |
| 状态迁移 | 保留旧状态，逐步迁移到新状态管理 |
| API调整 | 先新增接口，切换调用，逐步废弃旧接口 |

## 重构检查清单

- [ ] 修改范围最小化
- [ ] 每步修改后功能正常
- [ ] ESLint 检查通过
- [ ] 有对应的测试或手动验证
- [ ] 代码可以正常构建
